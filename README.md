# campus_hub

A campus activity management backend service built with Go and MySQL.

## Features

- Health check
- Query activities from MySQL
- Create activities and persist them to MySQL
- JSON request and response handling
- Basic input validation

## Run

Load the local database configuration:

```bash
source .env.local
```

Start the server:

```bash
go run .
```

The server listens on:

```text
http://localhost:8080
```

## API

### Health Check

```text
GET /health
```

Example response:

```json
{
  "status": "OK"
}
```

### Get Activities

```text
GET /activities
```

Example response:

```json
[
  {
    "id": 1,
    "name": "Go Backend Workshop",
    "capacity": 30,
    "open": true
  }
]
```

If there are no activities, the response is an empty JSON array:

```json
[]
```

### Create Activity

```text
POST /activities
Content-Type: application/json
```

Example request:

```json
{
  "name": "Database Workshop",
  "capacity": 40
}
```

Example successful response:

```json
{
  "id": 6
}
```

A successful request returns:

```text
201 Created
```

The activity ID is generated by MySQL, and new activities are created with `open=true`.

## Validation

Invalid JSON, an empty activity name, or a non-positive capacity returns:

```text
400 Bad Request
```

Example error response:

```json
{
  "error": "name cannot be empty"
}
```

## Persistence Test

To verify that activities are stored in MySQL:

1. Start the server.
2. Create an activity with `POST /activities`.
3. Confirm it appears in `GET /activities`.
4. Stop and restart the Go server.
5. Call `GET /activities` again.
6. Confirm that the same activity still exists.

## Local Configuration

The application uses the following environment variables:

```text
DB_HOST
DB_PORT
DB_NAME
DB_USER
DB_PASSWORD
```

Local values are stored in `.env.local`.

Do not commit `.env.local`, database passwords, or other secrets.
